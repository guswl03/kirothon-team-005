# 선택 감지 호환성

시연 대상 프로그램에서 자동 선택 감지가 되는지 기록하는 표입니다. 담당: A.

## 측정 방법

1. `npm run compat`을 실행합니다. 3초의 대기 시간이 있습니다(`npm run compat -- 5`처럼 초를 바꿀 수 있습니다).
2. 대기 시간 안에 **측정할 프로그램으로 이동해 텍스트를 드래그하고, 커서를 선택한 글자 위에 그대로 둡니다**. 도구는 포커스된 컨트롤과 커서 아래 요소를 앱과 같은 순서로 확인합니다.
3. 출력된 표 한 줄을 아래 표에 붙여 넣고, "지연(초)"은 앱을 켠 상태에서 선택부터 결과 창이 뜰 때까지 직접 잰 값을 적습니다.

측정 도구는 선택된 텍스트의 내용이나 창 제목을 출력하지 않고 길이와 프로세스 이름만 출력합니다.

측정: 2026-11-14, 오프라인 간이 모드. 지연은 선택 완료 후 숨겨진 결과 창이 표시될 때까지의 단일 측정값이며, 약 0.1초 간격으로 창 표시를 확인했다. 검색과 문장 생성이 완료되기까지의 시간은 포함하지 않는다.

C 전달용(미전달): 메모장과 크롬은 드래그로 시연한다. 워드와 카카오톡은 드래그를 재확인하기 전까지 복사(`Ctrl+C`) 후 `Ctrl+Alt+Space` 또는 붙여넣기를 사용한다. 미지원 판정은 없었으며, 연락 대상이 정해지지 않아 직접 알리지는 못했다.

## 메신저 확인 체크리스트 (카카오톡, 디스코드)

자동 검증으로는 확인할 수 없는 항목입니다. 에이전트가 실행한 프로세스는 다른 앱에 키 입력을 보낼 수 없었습니다(SendInput, SendKeys 모두 대상에 도달하지 않음). 그래서 복사 대체 경로는 사람이 직접 켠 앱에서만 확인할 수 있습니다.

준비: `npm start`로 앱을 켜고 자동 분석을 켭니다. 각 메신저에서 대화 말풍선 하나를 드래그합니다.

| # | 확인 | 카카오톡 | 디스코드 |
|---|---|---|---|
| 1 | `npm run compat`으로 말풍선 드래그 판정 기록(표에 붙여 넣기) | | |
| 2 | 옵션 꺼짐: 말풍선 드래그 시 결과 창이 뜨는지. 판정이 "지원(커서 아래)"면 떠야 함 | | |
| 3 | 옵션 꺼짐: 판정이 "복사 옵션 필요"면 미지원 안내가 한 번 뜨고 트레이 옵션을 알려 주는지 | | |
| 4 | 트레이 메뉴에서 "메신저 드래그 복사"를 켜면 동의 창이 뜨는지. 취소하면 꺼진 채로 남는지 | | |
| 5 | 옵션 켜짐: 말풍선 드래그 시 결과 창에 드래그한 내용이 들어가는지 | | |
| 6 | 옵션 켜짐: 드래그 전에 복사해 둔 다른 텍스트가 드래그 후에도 클립보드에 그대로 있는지(메모장에 붙여 넣어 확인) | | |
| 7 | 옵션 켜짐: 채팅 입력란에 글자를 쓴 채 말풍선을 드래그해도 입력란 내용이 바뀌지 않는지 | | |
| 8 | 옵션 켜짐: Shift를 누른 채 드래그하면 복사하지 않는지 | | |
| 9 | 옵션 켜짐: 메모장·터미널에서 드래그해도 Ctrl+C가 보내지지 않는지(터미널 실행 중 명령이 끊기지 않음) | | |
| 10 | 드래그 후 결과 창이 뜨기까지 시간(초) | | |

## 판정 기준과 대응

- **지원(커서 아래)**: 포커스는 다른 곳(예: 채팅 입력란)에 있지만 커서 아래 요소에서 선택을 읽었습니다. 자동 분석으로 시연합니다.
- **복사 옵션 필요**: 허용 메신저인데 UI Automation으로는 선택을 읽지 못했습니다. 트레이의 "메신저 드래그 복사"를 켜고 위 체크리스트로 확인합니다.

- **지원**: 자동 분석으로 시연합니다.
- **미지원**: 앱이 한 번 안내를 띄웁니다. 시연에서는 텍스트를 복사(`Ctrl+C`)한 뒤 `Ctrl+Alt+Space`를 누르거나 붙여넣기를 씁니다.
- **지원(선택 없음)**: 선택 후 다시 측정합니다.
- 크롬/엣지가 미지원이면 `chrome://accessibility` 또는 `edge://accessibility`에서 접근성을 켠 뒤 다시 측정합니다.
