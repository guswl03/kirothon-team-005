## 남은 위험

- 위키백과 검색어에 선택 텍스트가 포함된다. 민감한 내용을 선택하지 않도록 동의 창에서 안내한다.
- Kiro CLI/OpenAI 호환 사용 시 외부 제공자의 보관 정책은 앱이 통제하지 못한다.
- Kiro 구독을 최종 사용자 서비스에 쓰는 것이 허용되는지는 미확인이다. 확인 전에는 오프라인 또는 팀 승인 Provider를 사용한다.
- 개발 도구 취약점(minimatch DoS)은 배포물 런타임에 포함되지 않는다. 패키징 시에만 사용된다.
- UI Automation 폴링은 이벤트 기반이 아니라 350ms 주기다. 포커스된 앱의 접근성 정보가 노출되는 범위에서 동작한다.
## A 영역 추가 검토 (데스크톱 통합, 2026-11-14)

Kiro semantic reviewer로 `src/main/*`, `src/native/selection.ps1`, `scripts/compat*`를 검토했다. 전문은 `docs/handoff/A-review.md`. 선택 텍스트나 창 제목이 새는 경로는 발견되지 않았고, 비밀번호 제외는 새 미지원 보고 경로에서도 유지된다.

| 지적 | 조치 |
|---|---|
| 제목 표시줄 이동, 파일 끌기에서도 미지원 안내가 뜸 | 드래그 시작 위치가 포커스된 컨트롤 영역 안일 때만 보고 |
| 안내 문구가 단축키 동작과 다름(단축키는 클립보드만 읽음) | "복사(Ctrl+C)한 뒤 Ctrl+Alt+Space" 로 수정 |
| 왼손잡이 마우스 설정에서 드래그 판정 반전 | `GetSystemMetrics(SM_SWAPBUTTON)`으로 주 버튼 결정 |
| 짧은 드래그 누락(350ms 폴링) | 마우스는 50ms 주기로 샘플링, 드래그 종료 즉시 읽기 |
| `powershell.exe`를 이름으로 실행 | `SystemRoot` 기준 절대 경로 사용(`compat.js` 포함) |
| 한글 프로세스 이름이 PID로 대체됨 | 유니코드 문자 허용 |
| 헬퍼 종료가 조용히 무시됨, stderr 미소비 | 예기치 않은 종료를 앱 안내로 알림, stderr는 내용을 읽지 않고 비움 |
| 동의 후 외부 AI로 바꿔도 재확인 없음 | 외부 공급자로 전환할 때 확인 창 표시, 거절 시 되돌림 |
| 동의 문구가 "드래그로 선택한 텍스트만"인데 키보드 선택도 읽음 | 문구를 "드래그나 키보드 선택 모두"로 정정 |
| PowerShell 헬퍼 정적 점검 없음 | `npm run check`에 파일 쓰기, 콘솔·오류 출력, 외부 실행, 비밀번호 제외 규칙 추가 (위반 코드를 넣어 탐지되는 것을 확인) |

### 남은 위험 (A 영역)

- 비밀번호 표시 토글로 평문이 된 입력란과 `IsPassword`를 노출하지 않는 컨트롤은 읽힌다. 클립보드 단축키 경로는 출처를 알 수 없어 제외할 수 없다.
- 더블 클릭, 키보드 선택, 터치·펜 선택은 "미지원" 안내 대상이 아니다(선택 읽기는 가능한 프로그램에서 정상 동작).
- 헬퍼의 `Add-Type`은 PowerShell 제한 언어 모드에서 막힐 수 있다. 이 경우 드래그 감지만 꺼지고 선택 읽기는 계속된다.
- 드래그 판정과 PID별 1회 보고 같은 PowerShell 내부 로직은 자동 테스트가 없다. 실제 프로그램 실측으로 확인한다(`docs/COMPATIBILITY.md`).

## 메신저 드래그 복사 옵션 검토 (A, 2026-11-14)

카카오톡·디스코드 말풍선은 UI Automation으로 선택을 알려 주지 않을 수 있어, 사용자가 켜는 복사 대체 경로를 추가했다. PRD 8장("자동 복사를 반복하는 방식은 기본 동작으로 가정하지 않는다")에 맞춰 기본은 꺼짐이다.

| 위험 | 대응 | 근거 |
|---|---|---|
| 다른 앱에 키 입력을 보냄 | 사용자가 동의하고 켠 경우만. 허용 목록(`COPY_APPS`: KakaoTalk, Discord 계열)만. 드래그 종료 때만(폴링 없음). 전면 창과 커서 아래 앱이 같은 허용 앱일 때만. 수정키를 누르고 있으면 보내지 않음 | `selection.ps1` `Test-CopyAllowed`, `check.js` 규칙 |
| 터미널 등에서 Ctrl+C가 실행 중단으로 동작 | 허용 목록에 터미널·편집기를 넣지 않음(테스트로 고정) | `test/desktop/watcher.test.js` |
| 사용자 클립보드 덮어쓰기 | 텍스트·HTML·RTF·이미지·파일 목록을 백업 후 복원. 클립보드를 못 열거나 되돌릴 수 없는 형식만 있으면 복사 자체를 하지 않음. 클립보드가 바뀌지 않으면 아무것도 하지 않음 | `Backup-Clipboard`, `Restore-Clipboard`(5가지 경우 실행 확인) |
| 클립보드 기록에 남음 | Windows 클립보드 기록(Win+V)과 클립보드 관리 앱에는 대신 복사한 내용이 남는다. 앱이 막을 수 없어 동의 창에 안내 | `main.js` `setCopyFallback` |
| 키 입력·클립보드 코드가 퍼짐 | `npm run check`가 키 입력은 `Invoke-CopyFallback` 안에서 `Test-CopyAllowed` 뒤에만, 클립보드 읽기는 `Backup-Clipboard`/`Invoke-CopyFallback` 안에서만, 호출은 한 곳, 출력은 `Emit` 한 곳인지 검사(위반 6종을 넣어 모두 실패하는 것 확인) | `scripts/check.js` |
| 비밀번호란 | 포커스·커서 아래 요소 어느 쪽이든 비밀번호란이면 읽기와 복사 모두 건너뜀 | `selection.ps1` |

남은 위험:
- 대신 누른 Ctrl+C를 메신저가 다르게 처리할 가능성(예: 선택이 없을 때 다른 동작)은 실기기에서만 확인할 수 있다. `docs/COMPATIBILITY.md` 메신저 체크리스트 7~9번.
- 백업하지 않는 클립보드 형식(앱 전용 형식)은 "되돌릴 수 없는 형식만 있음"일 때만 막는다. 지원 형식과 함께 있으면 그 전용 형식은 복원되지 않는다.
- 이 경로는 에이전트 환경에서 키 입력이 대상 앱에 도달하지 않아 종단 실행을 확인하지 못했다(사용자 확인 필요).
